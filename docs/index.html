PASSO A PASSO

Do pedido HTTP à resposta.

Antes de criar arquivos, entenda o caminho de uma chamada. Depois escolha a trilha que corresponde ao projeto que você gerou. A documentação não consegue detectar a resposta que você escolheu no CLI.

Antes de começar

Abra a pasta raiz do projeto no editor. Cada caminho começa nessa pasta. Se um bloco mostrar mais de um arquivo, os comentários identificam onde separar o conteúdo; não cole tudo em um único arquivo. Imports terminados em .js estão corretos em TypeScript neste template. Depois de criar as rotas, reinicie o servidor: elas são descobertas quando a aplicação inicia.

Quando uma camada falha, ela passa o erro adiante. No Express deste kit, o controller chama next(error) e o middleware global monta a resposta de erro.

Os exemplos usam OpenAPI habilitado para mostrar schemas Zod e Swagger. Se escolheu --no-openapi, não importe Zod: mantenha os mesmos arquivos e camadas, mas valide entradas com parsers manuais. O README gerado pelo seu projeto descreve essa opção.

Se escolheu --no-crud, crie os diretórios do exemplo com mkdir -p models schemas repositories services controllers e use o próximo número livre para a migration.

    Tipifique os dados persistidos

    Crie models/product.ts. Product descreve uma resposta já persistida; o body de criação é diferente, pois ainda não tem ID nem data.

    export interface Product {
  id: number;

  3. 03 · ZOD

    Valide e infira o tipo de entrada

    Crie schemas/product-schemas.ts. O middleware roda antes do controller: body inválido vai ao handler de erros; body válido chega parseado. z.infer reaproveita o mesmo contrato como tipo TypeScript.

    import { z } from 'zod';
export const createProductSchema = z.object({
  name: z.string().trim().min(1).max(120),
}).strict();
export type CreateProductInput = z.infer<typeof createProductSchema>;

// IDs vindos da URL chegam como texto; converta-os dentro do schema.
export const productIdSchema = z.object({
  id: z.coerce.number().int().positive(),
}).strict();
export type ProductIdParams = z.infer<typeof productIdSchema>;

    Resultado: o input é validado e tipado pela mesma definição, sem manter dois contratos separados. z.coerce.number() transforma o parâmetro de URL em number.

  4. 04 · REPOSITORY

    Escreva SQL parametrizado

    Crie repositories/product-repository.ts. O repository conhece PostgreSQL e devolve linhas Product, mas não sabe qual URL foi chamada.

    import { pool } from '../databases/postgres.js';
import type { Product } from '../models/product.js';
export class ProductRepository {
  /** Lista produtos ordenados pelo ID. */
  async findAll(): Promise<Product[]> {
    const result = await pool.query<Product>(
      'SELECT id, name, created_at FROM products ORDER BY id',
    );
    return result.rows.map((row) => ({ ...row, id: Number(row.id) }));
  }

  /** Insere um produto e retorna a linha criada. */
  async insert(name: string): Promise<Product> {
    const result = await pool.query<Product>(
      'INSERT INTO products (name) VALUES ($1) RETURNING id, name, created_at',
      [name],
    );
    const row = result.rows[0]!;
    return { ...row, id: Number(row.id) };
  }
}

    Resultado: $1 envia o texto como parâmetro SQL; não concatene a entrada do usuário na query. O PostgreSQL pode devolver BIGSERIAL como texto, por isso o exemplo converte id para number.

  5. 05 · SERVICE

    Implemente as regras de negócio

    Crie services/product-service.ts. O construtor recebe o repository (injeção de dependência). O service não importa Express; nele entram regras do domínio e coordenação de operações.

    import { ProductRepository } from '../repositories/product-repository.js';
import type { Product } from '../models/product.js';

export class ProductService {
  /** Recebe a camada de persistência deste recurso. */
  constructor(private readonly repository: ProductRepository) {}

  /** Delega a listagem ao repository. */
  list(): Promise<Product[]> {
    return this.repository.findAll();
  }

  /** Cria um produto com nome já validado pelo schema. */
  create(name: string): Promise<Product> {
    return this.repository.insert(name);
  }
}
  6. 06 · CONTROLLER

    Conecte a camada HTTP ao service

    Crie controllers/product-controller.ts. O controller recebe objetos do Express, lê o valor já validado, chama o service e escolhe status e JSON. next(error) entrega falhas ao middleware global.

    import type { NextFunction, Request, Response } from 'express';
import type { CreateProductInput } from '../schemas/product-schemas.js';
import { ProductService } from '../services/product-service.js';

interface ValidatedLocals {
  validated: { body?: CreateProductInput };
}

export class ProductController {
  /** Recebe as regras de negócio do produto. */
  constructor(private readonly service: ProductService) {}

  /** Lista produtos e responde em JSON. */
  list = async (_req: Request, res: Response, next: NextFunction): Promise<void> => {
    try { res.json({ data: await this.service.list() }); }
    catch (error) { next(error); }
  };

  /** Cria um produto e converte o resultado para HTTP. */
  create = async (_req: Request, res: Response, next: NextFunction): Promise<void> => {
    try {
      const locals = res.locals as unknown as ValidatedLocals;
      const { name } = locals.validated.body!;
      const product = await this.service.create(name);
      res.status(201).json({ data: product });
    } catch (error) { next(error); }
  };
}

    Resultado: se a criação der certo, o cliente recebe 201 Created; se falhar, a cadeia de erro responde.

  7. 07 · ROUTE + OPENAPI

    Conecte as camadas e descreva o contrato

    Crie routes/products.route.ts. A rota monta as dependências. O path '/' é relativo ao prefixo routePath, então forma POST /products. OpenAPI exige o caminho completo.

    import { Router } from 'express';
import { z } from 'zod';
import { ProductController } from '../controllers/product-controller.js';
import { ProductRepository } from '../repositories/product-repository.js';
import { ProductService } from '../services/product-service.js';
import { validateRequest } from '../middlewares/validate.js';
import { createProductSchema } from '../schemas/product-schemas.js';

const router = Router();
const controller = new ProductController(
  new ProductService(new ProductRepository()),
);

/** Prefixo montado pelo carregador de rotas. */
export const routePath = '/products';
router.get('/', controller.list);
router.post('/', validateRequest({ body: createProductSchema }), controller.create);

const productSchema = z.object({
  id: z.number(), name: z.string(), created_at: z.string().datetime(),
});
const productListResponseSchema = z.object({ data: z.array(productSchema) });
/** Operações que o carregador adiciona ao OpenAPI. */
export const openApiPaths = [{
  method: 'get' as const,
  path: '/products',
  summary: 'Lista produtos',
  responses: { 200: { description: 'Lista de produtos', content: {
    'application/json': { schema: productListResponseSchema },
  } } },
}, {
  method: 'post' as const,
  path: '/products',
  summary: 'Cria um produto',
  request: { body: { required: true, content: { 'application/json': { schema: createProductSchema } } } },
  responses: { 201: { description: 'Produto criado', content: {
    'application/json': { schema: z.object({ data: productSchema }) },
  } } },
}];

export default router;

    O loader importa arquivos *.route.ts e monta o router. Não edite app.ts. Se a rota responder mas não aparecer no Swagger, confira openApiPaths e o caminho absoluto.

  3. 03 · SERVICE

    Escolha de onde vêm os dados

    Sem PostgreSQL, não há repository SQL. Este service em memória serve para aprender o fluxo ou prototipar; não persiste dados após reiniciar.

    import type { Product } from '../models/product.js';

const products: Product[] = [];

export class ProductService {
  /** Lista os produtos deste protótipo. */
  list(): Product[] { return products; }

  /** Cria um produto temporário em memória. */
  create(name: string): Product {
    const product = {
      id: products.length + 1,
      name,
      created_at: new Date().toISOString(),
    };
    products.push(product);
    return product;
  }
}

    Para dados duráveis, integre uma fonte real e crie um repository para escondê-la do service.

  4. 04 · CONTROLLER

    Trate a requisição HTTP

    Crie controllers/product-controller.ts. O cast de res.locals informa ao TypeScript o tipo validado; next(error) passa falhas ao Express.

    import type { NextFunction, Request, Response } from 'express';
import type { CreateProductInput } from '../schemas/product-schemas.js';
import { ProductService } from '../services/product-service.js';

interface ValidatedLocals {
  validated: { body?: CreateProductInput };
}

export class ProductController {
  /** Recebe o service deste recurso. */
  constructor(private readonly service: ProductService) {}

  /** Lista produtos e envia a resposta HTTP. */
  list = (_req: Request, res: Response): void => {
    res.json({ data: this.service.list() });
  };

  /** Cria um produto e envia a resposta HTTP. */
  create = async (_req: Request, res: Response, next: NextFunction): Promise<void> => {
    try {
      const locals = res.locals as unknown as ValidatedLocals;
      const { name } = locals.validated.body!;
      res.status(201).json({ data: this.service.create(name) });
    } catch (error) { next(error); }
  };
}
  5. 05 · ROUTE + OPENAPI

    Registre e valide o endpoint

    Crie routes/products.route.ts. O middleware valida o body antes de chamar o controller. Com OpenAPI habilitado, declare a operação para que ela apareça em /docs.

    import { Router } from 'express';
import { z } from 'zod';
import { ProductController } from '../controllers/product-controller.js';
import { ProductService } from '../services/product-service.js';
import { validateRequest } from '../middlewares/validate.js';
import { createProductSchema } from '../schemas/product-schemas.js';

const router = Router();
const controller = new ProductController(new ProductService());

/** Prefixo montado automaticamente. */
export const routePath = '/products';
router.get('/', controller.list);
router.post('/', validateRequest({ body: createProductSchema }), controller.create);

const productSchema = z.object({
  id: z.number(), name: z.string(), created_at: z.string().datetime(),
});
/** Caminho absoluto documentado no Swagger. */
export const openApiPaths = [{
  method: 'get' as const,
  path: '/products',
  summary: 'Lista produtos em memória',
  responses: { 200: { description: 'Lista de produtos', content: {
    'application/json': { schema: z.object({ data: z.array(productSchema) }) },
  } } },
}, {
  method: 'post' as const,
  path: '/products',
  summary: 'Cria um produto',
  request: { body: { required: true, content: { 'application/json': { schema: createProductSchema } } } },
  responses: { 201: { description: 'Produto criado', content: {
    'application/json': { schema: z.object({ data: productSchema }) },
  } } },
}];

    Se escolheu --no-openapi, substitua Zod por um parser manual e remova openApiPaths. O arquivo de rota continua funcionando sem Swagger.
